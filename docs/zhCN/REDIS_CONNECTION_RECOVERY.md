# Redis 连接恢复

Redis 初次连接失败不再让本进程永久丢失已配置的后端。首次验证沿用 redis-kit 的超时和连接设置；验证失败时，保留相同设置的新惰性客户端，因为 redis-kit 会关闭验证失败的客户端。

本次启动不追加 Redis 引导或写入者选举，来源仍按原行为加载到内存。启动完成后，已有命令使用 go-redis 有界连接和命令重试按需重连，不新增重试循环、不替换客户端，也不把共享写入降级为本地锁。

旧缓存、V2 store、租约、健康探针和 Redis 重放保护始终引用同一个客户端。Redis 关闭模式与缓存格式不变。启用 Redis 的 HMAC 部署在 Redis 不可用时拒绝 HMAC v2；API Key/mTLS 继续遵守既有认证链。

重连本身不产生新的来源成功证据。V2 恢复沿用持久化来源时间，成功来源刷新沿用已有发布路径。
