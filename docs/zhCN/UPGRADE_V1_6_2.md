# Warden v1.6.2 升级与回滚

本补丁更新 `secure-kit/v2` 和 `audit-kit/v2` 至 v2.1.4，并发布 v1.6.1 后合并的
当前文档及示例修正。公开 SDK API、JSON 响应结构、返回错误链、HMAC 协议、Redis 快照格式、
来源版本及新鲜度默认策略均不变，不需要转换数据或迁移命名空间。

## 变化范围

相关脱敏函数改为按 Unicode 码点边界处理非 ASCII 文本，避免截断 UTF-8 或返回无关
字符。ASCII 及短输入行为保持不变；身份哈希、签名和加密算法不变。这不会清洗调用方
任意日志消息或返回错误，也不会改写已有日志、审计行。

当前说明已按实现修正鉴权分支、严格服务策略、SDK 日志与重试、快照元数据及 503
响应契约。示例修正了 API Key、Redis 密码、shell 参数、私网来源、工作目录和端口。
HTTP 模拟源仍仅用于开发，不构成生产部署模板。

## 升级与回滚

1. 服务升级为 v1.6.2；SDK 使用方执行 `go get github.com/soulteary/warden@v1.6.2`
   并重建。仅更新后端不会替换其他程序中已经编译的 SDK 或依赖。
2. 保留现有配置、Redis 数据和命名空间。生产仍要求 HTTPS 来源且默认
   `SNAPSHOT_READ_POLICY=enforce`；未知或过期来源仍会被拒绝。
3. 核对依赖非 ASCII 脱敏输出的处理逻辑，不能将脱敏文本当作稳定身份标识。
   回滚二进制时保留修正后的部署和示例配置，尤其是 Redis 服务端与客户端一致的密码；
   直接恢复旧示例文件也会恢复其已有配置错误。
4. 服务回滚到 v1.6.1 使用相同存储状态和该二进制原有依赖。SDK 使用方应恢复应用
   升级前的 `go.mod`/`go.sum` 后重建；仅降低 Warden 版本不一定降低 audit-kit 或
   secure-kit。用 `go list -m` 核实实际选中版本，不要违背其他依赖的版本要求强行
   降级，也不能在仍选中新版依赖时声称旧脱敏行为已恢复。回滚不改写既存内容，
   不恢复已消费 nonce，不需要清空 Redis。

早于 v1.6.0 的部署仍须遵循[该版本迁移要求](../releases/v1.6.0.md)，
[v1.6.1 的 SDK 日志边界](../releases/v1.6.1.md)也继续适用。
使用隔离合成数据验证正常鉴权、快照读取和旧新旧兼容性；发布后核对签名 tag、源码、
正式 Go 模块校验和、公开资产哈希、SBOM 和 OCI digest 签名。
