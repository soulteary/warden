# 空名单与加载失败契约

本文记录相同本地及远程数据通过 HTTP 明文和真实 v2 envelope 加密传输时，
`RulesLoader.LoadWithResult` 的现有结果，不改变合并模式、缓存发布或健康检查行为。

## 成功加载的空集

测试使用单个本地文件和一个远程 API。以下场景中，两种传输方式结果相同：

- 两个来源都返回 `[]`：七种模式均成功返回空集合。
- 远程返回 `[]`、本地有用户：`ONLY_REMOTE` 返回空集，其他模式返回本地用户。
  合并模式下，远程空数组不会清除本地授权。
- 本地返回 `[]`、远程有用户：`ONLY_LOCAL` 返回空集，其他模式返回远程用户。
- 本地 JSON 损坏、远程有用户：`ONLY_LOCAL` 失败，其他模式返回远程用户且不标记降级。

`ONLY_LOCAL` 与应用一样不传远程 URL；这不代表验证了向底层 loader 显式传入远程
URL 时也会忽略它。

## 远程失败，本地有有效非空数据

下表同时适用于远程 HTTP 404 和远程用户 JSON 损坏。加密 JSON 场景使用经过完整性
校验的合法 v2 envelope，其内部用户 JSON 损坏；失败点是用户解码，不是认证。

| 模式 | 明文结果 | 加密结果 |
| --- | --- | --- |
| `DEFAULT` | 本地用户，不降级 | 本地用户，降级 |
| `REMOTE_FIRST` | 错误 | 错误 |
| `ONLY_REMOTE` | 错误 | 错误 |
| `ONLY_LOCAL` | 本地用户，不降级 | 本地用户，不降级 |
| `LOCAL_FIRST` | 本地用户，不降级 | 本地用户，降级 |
| `REMOTE_FIRST_ALLOW_REMOTE_FAILED` | 本地用户，降级 | 本地用户，降级 |
| `LOCAL_FIRST_ALLOW_REMOTE_FAILED` | 本地用户，不降级 | 本地用户，降级 |

降级结果的原因均为 `remote_failed`。即使用户授权记录相同，回退诊断仍有可观察的
差异。测试保留两种现有结果，不会悄悄将明文路径改成解密路径的行为。

## 远程失败，本地为空集

远程 HTTP 404 且本地为 `[]` 时，两种传输下除 `ONLY_LOCAL` 外均加载失败；
`ONLY_LOCAL` 不传远程 URL，成功加载本地空集。空回退不等于远程刷新成功。
失败结果不包含用户或版本，调用方不能把它作为新空规则集采纳。
应用如何处理旧快照由其他测试覆盖。

## 测试边界

`internal/loader/transport_fallback_contract_test.go` 中的
`TestTransportFallbackContract` 覆盖七种场景、七种模式、两种传输，断言完整用户
记录、错误、降级标记和原因，以及成功结果的内容版本。测试使用真实 HTTP 响应及
`remote.Encrypt`，不模拟内部合并函数；不要求两条路径的错误文本、来源标签、
时间戳或记录顺序一致。

范围限定为单文件、单远程 API、v2 加密、HTTP 404 和用户 JSON 损坏。目录顺序、
零字节响应、超时、信封篡改、旧版加密、缓存层格式过滤已有其他测试或需单独评审，
不能从本矩阵推广其行为。

快照及调用方缓存边界参见[当前数据契约](DATA_CONTRACT.md)。
