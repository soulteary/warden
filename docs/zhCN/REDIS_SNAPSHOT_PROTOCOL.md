# 版本化 Redis 快照协议

此存储 API 为增量能力；在显式开启迁移模式前，旧用户数组缓存及应用选择方式不变。

v2 保存生效用户、内容摘要、输入版本和数量、原始来源类型、来源成功时间、发布时间
及发布修订号。来源成功指一次被采纳的来源加载，不代表上游业务内容刚更新。恢复时间
属于本进程，不作为来源证据持久化。

每个数据集须显式指定命名空间及策略指纹。快照和租约使用同一 Redis Cluster hash tag。
读取原子地区分键缺失与合法空集；拒绝未知格式或策略、null 用户、错误摘要、异常时间
和过大载荷，错误不包含原始数据。允许最多五秒的未来时钟偏差。
`SNAPSHOT_READ_POLICY=enforce` 的读取判定使用同一允许量，因此存储接受的发布不会被
恢复它的副本以来源时间在未来为由拒绝；超出该允许量的来源时间两处均拒绝。

写入者须在加载来源前取得 Redis 所有者令牌租约，发布时原子核对所有权。过期写入者
不能发布或删除继任者租约。租约有界且不自动续租，慢任务过期后跳过共享发布，下一
刷新周期重试。Redis 故障不降级为进程内所有权。

续期比较当前发布修订号，仅修改 TTL，不改写用户、来源成功时间或发布时间。
旧副本即使持有相同用户内容，也不能续期或恢复更新的发布。刷新被拒绝后保留上一次
有效集合的副本，仅在 Redis 中没有来源成功时间相同或更晚的可读发布时才发布该集合。
续期时若快照键完全不存在，或存储值不是本数据集和策略的发布，租约持有者按同一规则
重新发布自己持有的快照，保留原来源成功时间并生成新的修订号；这样的值不是本数据集
和策略的任何副本可以恢复的发布。若存储值是本数据集和策略的发布且修订号不同，说明
其他写入者可能已发布，存储值保持不动。
部署仍须保证时钟同步及
Redis 写入者可信；此格式不等同于带签名的上游版本协议。

续期脚本在比较修订号之前先判定存储值是什么，并返回以下结果之一：

| 结果 | 存储值 | 续期结果 | 租约持有者 |
| --- | --- | --- | --- |
| 0 | 未检查：租约已不再持有 | `lease_lost` | 不写入 |
| 1 | 本数据集和策略的发布，修订号与持有的相同 | `renewed` | 延长 TTL |
| 2 | 本数据集和策略的发布但修订号不同，或声明了更高 `schema_version` 的值 | `revision_conflict` | 保持存储值不动 |
| 3 | 键不存在 | `missing` | 重新发布 |
| 4 | 长度超过 `MAX_ENVELOPE_JSON_SIZE` | `too_large` | 重新发布 |
| 5 | 不是快照 | `invalid_envelope` | 重新发布 |
| 6 | 其他数据集的快照 | `dataset_rejected` | 重新发布 |
| 7 | 其他策略的快照 | `policy_rejected` | 重新发布 |

满足以下任一条件的值是本数据集和策略的发布：

- 以本数据集和策略的每个快照都具有的开头字节（见下文）开始，其后是 32 个 `0-9a-f`
  字符以及 `users` 成员的开头；或
- 被 Redis 解码为 JSON 对象，其 `schema_version` 是数字 2，`dataset` 和 `policy`
  与本存储相同，`revision` 是由 32 个 `0-9a-f` 字符组成的字符串。

声明了更高格式版本的值是指：以 `{"schema_version":` 开头且其后是大于 2 的整数和 `,` 或 `}`，
或被 Redis 解码为 `schema_version` 是大于 2 的数字的对象。本版本无法判断这样的值
是否为一次发布，而升级期间更新的版本可能正在同一键下写入它，因此无论其他成员如何，
都按其他写入者的发布处理并保持不动。第一种形式无需解码即可识别，也不要求值的其余
部分是合法 JSON。

其余的值都不是快照（结果 5）：无法被 Redis 解码为 JSON 对象或数组的值、数组、`{}`、
没有 `schema_version` 或其值小于 2 或不是数字的对象、`dataset` 或 `policy` 缺失或
不是字符串的对象，以及 `revision` 缺失、不是字符串或不是 32 个 `0-9a-f` 字符的对象。
格式版本为 2、`dataset` 和 `policy` 形式正确但与本存储不同的对象，在检查修订号之前
即报告为结果 6 或 7。

共用命名空间但策略不同的副本会各自把对方的发布判定为其他策略的快照，并在自己的
周期内替换它。不同策略应按 [Redis 快照迁移](REDIS_SNAPSHOT_MIGRATION.md) 的要求
使用不同命名空间。

以上规则只适用于续期。未持有修订号的副本，以及来源加载成功后的任何副本，发布时
与此前一样不检查存储值的格式版本。

续期从存储值的开头读取修订号。每个快照都以 `schema_version`、`dataset`、`policy`、
`revision` 依次开头且不含空白，其后是 `users`。脚本将该开头与本数据集和策略应有的
开头比较，因此不在 Redis 内解码用户列表，用户记录中的任何内容也不会参与比较。
开头不同的值，除声明了更高格式版本的值外，仍按上文完整解码并分类。这些开头成员的顺序属于存储格式的一部分：
改变顺序的写入者仍能被正确续期，但每次续期都会重新解码整个值。

协议测试使用 miniredis 的真实 Lua 执行，覆盖租约过期、继任者、陈旧续期、空集、
损坏快照及重启恢复。应用迁移和旧格式兼容由独立改动实现。
