# Warden v1.6.1 升级与回滚

本补丁发布 v1.6.0 后合并的 SDK 内部诊断日志修复和当前文档修正。Go 1.27.3、
公开 SDK 签名、JSON 响应、返回错误链、鉴权和存储格式均不变。不需要转换 Redis
数据；v1.6.0 的生产默认策略继续生效。

## SDK 日志

显式配置 SDK Logger 时，网络失败消息可能包含带手机号或邮箱查询参数的 URL；
重试消息也会打印 URL，非 200 响应诊断会打印响应体。本补丁在这些内部失败路径
只记录允许的 SDK 错误类别、HTTP 状态码及固定文本，不输出原始错误、重试 URL
或响应体。默认仍为 `NoOpLogger`；这是已有的可选日志暴露，不是鉴权绕过。

返回错误仍保留原有详情和包装关系，包括 `errors.Is` 行为。业务代码若自行记录
这些错误，仍须制定自己的日志策略。公开 `Logger` 接口和适配器不会自动清洗调用方
传入的任意消息；本补丁不保证全部 SDK、业务或代理日志都已脱敏。

## 升级

1. SDK 使用方执行 `go get github.com/soulteary/warden@v1.6.1` 并重新构建。
   仅升级 Warden 服务不会替换其他应用中已经编译的 SDK。
2. 检查依赖原始错误文本或重试 URL 的日志解析规则，改用错误类别和 HTTP 状态码。
   已有日志不会自动改写；若曾启用自定义 SDK 日志，按实际情况检查其访问权限和保留期。
3. 保留现有部署配置、Redis 数据和命名空间。生产默认 `SNAPSHOT_READ_POLICY=enforce`，
   开发/测试默认 `observe`，这与 v1.6.0 相同。旧格式 Redis 恢复缺少来源年龄证据，
   在 enforce 下必须成功加载来源后才可服务数据；切换存储格式不会改变读取策略。
4. 仅使用合成标识和隔离 Redis 验证成功读取、网络失败、来源过期与重启恢复。
   当前[数据契约](DATA_CONTRACT.md)和[迁移说明](REDIS_SNAPSHOT_MIGRATION.md)
   已修正此前关于默认 observe 的矛盾描述。

## 回滚

服务或 SDK 回滚到 v1.6.0 时，生产 enforce 默认值不变，不会因此允许读取未知或过期
来源数据。SDK 回滚会恢复此前诊断日志行为；可停用自定义 SDK Logger，避免再次记录
受影响的失败路径。应用自行记录返回错误的风险不由本次内部日志修复覆盖。

从更早版本升级还须遵循 [v1.6.0 发布说明](../releases/v1.6.0.md)的 HTTPS、重定向、
凭据和 Redis 要求。产物核验步骤见[英文补丁说明](../releases/v1.6.1.md)。
