# Redis 快照迁移

即使使用 YAML，以下两个迁移选项也只从环境变量读取。

- `REDIS_SNAPSHOT_MODE=legacy`：默认值。继续使用旧数组缓存，保留原有引导、TTL、健康年龄计算和 HTTP 字段，不读写 V2。
- `shadow`：旧缓存仍是读取与写入依据。旧写入成功后，持有 V2 租约且来源时间已知时附加写入 V2；V2 失败不撤销旧写入。恢复时不读取 V2。
- `v2`：只读写 V2。缺失、损坏、超限或策略不兼容时继续原有来源加载，不自动回退或转换旧数组。

shadow/v2 要求启用 Redis，并设置 `REDIS_SNAPSHOT_NAMESPACE`：1–64 个字母、数字、冒号、下划线或连字符，首位为字母或数字。每个逻辑数据集使用独立命名空间。策略指纹覆盖合并模式、身份策略、空集合策略和加密路径；不匹配时拒绝恢复，必须重新加载来源。不同策略并行运行时使用不同命名空间。

## 三种时间

`source_succeeded_at` 是接受并验证完成的最终来源集合时间，包括内容相同的成功复查。允许的本地回退只证明本地集合有效，不表示远端成功。失败、拒绝输入、保留旧集合均不推进它。

`published_at` 是 V2 成功发布时间。重新验证后发布相同内容会生成新修订；只续 TTL 不改变它。`restored_at` 是本进程恢复时间，不写回为来源时间。

shadow/v2 来源快照和 V2 恢复在快照健康元数据中显示已知时间和 `origin`，未知时间省略。旧数组的来源年龄未知，不能以恢复时间冒充来源时间生成 V2。

V2 的 `loaded_at`、`age_seconds`、新鲜度健康检查和年龄指标使用来源成功时间；续期和重启不会让旧数据变新。默认仍可按原有策略用过期快照服务查询；显式严格读取策略可返回 503，存储迁移本身不会启用该策略。原始输入数量和版本持久化，保留“全部被过滤”与“真实空集合撤销”的区别。

## 部署与回滚

1. 先以默认 legacy 部署。构建和验证使用 Linux，其他主机使用容器。
2. 选择命名空间，使用相同加载策略部署 shadow，确认来源刷新成功且 V2 已写入。仅从旧缓存恢复或来源加载失败无法建立第一份可信时间基线。
3. 启用 V2 前停止并排空 legacy/shadow 写入者，确认 V2 足够新且策略一致，否则先完成来源刷新。租约一分钟，不自动延长；慢加载超过租约后跳过共享写入。各副本仍独立加载并可使用本地成功结果。
4. 观察新鲜度、失败计数与 Redis 错误。回滚窗口内保留旧键。V2 使用 `warden:{namespace}:snapshot:v2` 及独立租约，不与旧写入者隐式协调。
5. 回滚先排空 V2，再切回 legacy/shadow。V2 不更新旧键，旧缓存可能过期或陈旧，应先恢复成功的来源刷新。旧恢复重新使用恢复时间计算年龄，无法保留旧格式未存储的时间证据。

本迁移不改变合并优先级、格式验证、授权、调度、空集合默认策略和查询新鲜度执行方式。时间来自可信进程时钟，不是上游签名时间；Redis 权限与时钟同步仍是运行前提。协议见 [存储设计](REDIS_SNAPSHOT_PROTOCOL.md)。
