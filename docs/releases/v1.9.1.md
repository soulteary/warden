# Warden v1.9.1

This release corrects one log line of the Go SDK (`pkg/warden`). The service
is unchanged: HTTP routes, responses, configuration, logs, metrics and the
Redis formats are those of v1.9.0, and the image is built from the same
service code. Dependencies, the Go version (1.27.4) and the build image are
those of v1.9.0.

## SDK consumers

- When Warden answers 429, `CheckUserInList` writes the debug line
  `Failed to get user from Warden API: code=RATE_LIMITED (...)` to the
  configured `Logger`. v1.8.0 and v1.9.0 wrote `code=UNKNOWN` in that line.
- Error codes, messages, `Error.StatusCode`, `Error.RetryAfter` and return
  values are unchanged. No other log line changes.
- A log filter or alert that matches `code=UNKNOWN` for rate-limited lookups
  must match `code=RATE_LIMITED`.

## Upgrade and rollback

```sh
go get github.com/soulteary/warden@v1.9.1
```

- Service: v1.9.0 and v1.9.1 replicas can run together in any order. No
  setting, ACL or stored data changes in either direction.
- SDK: no source change is needed in either direction. To roll back, restore
  the application's pre-upgrade `go.mod` and `go.sum` and rebuild.

For versions older than v1.9.0, apply the [v1.9.0 notes](v1.9.0.md) and the
[v1.8.0 upgrade checks](v1.8.0.md) first.

## Verification

Verify the signed tag and source commit, the Go module checksum, the release
workflow run, the asset hashes in `checksums.txt`, the SPDX SBOM, and the image
digest with its keyless signature. `warden --version` prints the version,
commit and build date of a binary.
