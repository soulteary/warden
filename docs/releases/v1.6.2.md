# Warden v1.6.2

This patch updates `secure-kit/v2` to v2.1.4 and `audit-kit/v2` to v2.1.4, and
publishes current documentation and example corrections merged after v1.6.1.
Public SDK APIs, JSON response schemas, returned error chains, HMAC protocols, Redis
snapshot formats, source versions and freshness defaults remain unchanged.

## Dependency and documentation changes

Unicode masking now follows code-point boundaries in the secure-kit helpers
used by Warden log adapters and audit destination masking. ASCII and short-input
behavior remains unchanged. This does not change identity hashing, request
signatures or encryption. It does not sanitize arbitrary caller messages or
returned errors, and existing logs/audit rows are not rewritten.

Current documentation describes per-request authentication, the strict service
policy profile and negotiated snapshot metadata/plain-text freshness refusals.
Examples now use matching API keys and Redis passwords, quoted shell arguments,
explicit development/private-source settings and consistent host/container ports.
The HTTP mock remains a development example, not a production deployment profile.

## Upgrade and rollback

```sh
go get github.com/soulteary/warden@v1.6.2
```

- Rebuild SDK consumers as well as upgrading the service. Updating only the
  backend does not replace dependencies already compiled into another program.
- Keep existing configuration, Redis datasets and namespaces. No JSON, source or
  snapshot conversion is required for this patch. Production still requires
  HTTPS sources and uses `SNAPSHOT_READ_POLICY=enforce`; development/test keeps
  its documented policy. Unknown or expired source evidence is still refused.
- Keep the corrected deployment/example settings when rolling binaries back.
  Reverting example files also restores their earlier setup mistakes; in
  particular, retain matching Redis server/client password configuration.
- Review consumers of non-ASCII masked output. Masked text is not a stable user
  identifier, and this patch does not alter canonical identity hashes.
- The v1.6.1 service binary uses the same stored state and its earlier compiled
  dependency graph. For SDK consumers, restore the application's pre-upgrade
  `go.mod`/`go.sum` and rebuild; downgrading Warden alone may leave newer
  audit-kit/secure-kit selected. Verify with `go list -m` before claiming older
  masking behavior. Do not force a dependency downgrade against another module's
  required version. Rollback does not rewrite stored records or reverse consumed
  nonces. Do not clear Redis.

For versions older than v1.6.0, retain the
[v1.6.0 migration requirements](v1.6.0.md). The
[v1.6.1 SDK logging boundaries](v1.6.1.md) also remain applicable. See the
[Chinese patch guide](../zhCN/UPGRADE_V1_6_2.md).
