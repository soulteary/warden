# Warden v1.9.0

This release adds one field to the Go SDK (`pkg/warden`). The service is
unchanged: HTTP routes, responses, configuration, logs, metrics and the Redis
formats are those of v1.8.0, and the image is built from the same service code.
Dependencies, the Go version (1.27.4) and the build image are those of v1.8.0.

## SDK consumers

- `warden.Error` has a `StatusCode` field with the HTTP status of the Warden
  response that the error reports, for example 401, 403, 404, 429 or 503. It
  is 0 when the error does not come from a response status: invalid
  configuration, a request that got no response, a body that could not be
  decoded, or a source freshness failure.
- Error codes and messages are unchanged. A 403 keeps the code
  `REQUEST_FAILED` and can be recognized with
  `StatusCode == http.StatusForbidden`.
- Code that builds a `warden.Error` with an unkeyed composite literal no longer
  compiles; name the fields or use `warden.NewError`.

## Upgrade and rollback

```sh
go get github.com/soulteary/warden@v1.9.0
```

- Service: v1.8.0 and v1.9.0 replicas can run together in any order. No
  setting, ACL or stored data changes in either direction.
- SDK: the v1.9.0 SDK works against a v1.8.0 service and the v1.8.0 SDK
  against a v1.9.0 service. To roll back, restore the application's
  pre-upgrade `go.mod` and `go.sum`, remove uses of `StatusCode` and rebuild.

For versions older than v1.8.0, apply the
[v1.8.0 upgrade checks](v1.8.0.md) first.

## Verification

Verify the signed tag and source commit, the Go module checksum, the release
workflow run, the asset hashes in `checksums.txt`, the SPDX SBOM, and the image
digest with its keyless signature. `warden --version` prints the version,
commit and build date of a binary.
