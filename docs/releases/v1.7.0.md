# Warden v1.7.0

This release adds environment variables for rate limiting and for Redis ACL and
TLS connections, and tightens several security defaults. Some configurations
that started under v1.6.3 are now refused at startup, and a few responses
change; review the upgrade checks below before upgrading production.

Public SDK method signatures, HMAC protocols, Redis snapshot formats and stored
data are unchanged. No data conversion is required. The module now declares
Go 1.27.4.

## New configuration

- `RATE_LIMIT` and `RATE_LIMIT_WINDOW` override `rate_limit.rate` and
  `rate_limit.window` from the configuration file. The window accepts a
  duration or a number of seconds, with a minimum of one second. Invalid values
  stop startup. The default remains 60 requests per minute per client IP.
- `REDIS_USERNAME` selects a Redis ACL user. `REDIS_TLS_ENABLED`,
  `REDIS_TLS_CA_FILE` and `REDIS_TLS_SERVER_NAME` configure a TLS connection to
  Redis. The server certificate is always verified. TLS is off by default, and
  the CA file and server name require `REDIS_TLS_ENABLED=true`.

See [configuration](../enUS/CONFIGURATION.md) and
[security](../enUS/SECURITY.md).

## Upgrade checks

Startup is now refused in these cases:

- Redis is enabled and `REDIS_PASSWORD_FILE` or `redis.password_file` is
  configured but unreadable or empty. Warden previously ignored the error and
  connected without a password.
- A `TRUSTED_PROXY_IPS` entry is not an IP address or CIDR range, for example a
  hostname or an address with a port. Such entries were previously dropped.
- `ENVIRONMENT=production` and `API_KEY` is one of the placeholder values from
  the documentation and examples. Generate a key, for example with
  `openssl rand -hex 32`. A key shorter than 16 characters logs a warning.
- `RATE_LIMIT`, `RATE_LIMIT_WINDOW` or `REDIS_TLS_ENABLED` has an invalid value,
  or the configuration file sets a negative `rate_limit.rate` or a
  `rate_limit.window` below one second.

Request handling changes in these cases:

- `rate_limit.rate` and `rate_limit.window` from the configuration file now take
  effect. They were parsed but the limiter always ran at 60 requests per
  minute. A deployment whose file sets other values will see them applied.
- `/metrics` and `/log/level` are subject to the rate limit and the 10 KB
  request body limit, and share the per-client budget of the data endpoints. A
  scraper that polls faster than the configured limit receives 429. Health
  check endpoints are not rate limited.
- A request with HMAC headers and a body larger than 10 KB is rejected before
  its signature is checked. `POST`, `PUT`, `PATCH` and `DELETE` requests whose
  `Content-Length` exceeds the limit receive 413 from the body-limit
  middleware, as they did before. `GET`, `HEAD` and `OPTIONS` requests with a
  body, and requests without a `Content-Length` (chunked), receive 401; their
  body was previously read in full.
- `RESPONSE_FIELDS` now applies to `/v1/lookup`. `user_id`, `status`,
  `channel_hint` and the `destination` object are always returned. `mail`
  governs `destination.email`, `phone` governs `destination.phone`, and `name`
  and `dingtalk_userid` govern the fields of the same name. Deployments that
  set `RESPONSE_FIELDS` and use `/v1/lookup` for code delivery must include
  `mail` and/or `phone`, and `dingtalk_userid` when codes are delivered through
  DingTalk. The documented example value
  `phone,mail,user_id,status,name` does not include `dingtalk_userid`. Field
  names are matched exactly and are case-sensitive; an unknown name such as
  `email` or `Mail` is not reported and leaves the field out. With an empty
  allowlist the response is unchanged.
- A rate-limited request receives 429 with the plain-text body
  `Too Many Requests` and no `Retry-After` header. In production the body is
  the JSON object `{"error":"..."}`, still sent as `text/plain`.
- The `http.url` trace attribute no longer includes the query string.
- List, user and lookup responses of 1 KB or more now carry
  `Content-Encoding: gzip` when they are compressed.
- New audit log files are created with mode 0600 and new log directories with
  mode 0700. Existing files and directories keep their mode. A process that
  reads the audit log under another account needs access granted explicitly.

Warden logs a startup warning when `IP_WHITELIST` is set and
`TRUSTED_PROXY_IPS` is empty. The default is unchanged: forwarded addresses are
then trusted from any private or loopback peer. Set `TRUSTED_PROXY_IPS` to the
addresses of your reverse proxies.

The `example/basic` and `example/advanced` Compose files require `API_KEY` to be
set and publish their ports on `127.0.0.1` only.

## Dependencies

Go is updated to 1.27.4, which fixes GO-2026-6859 in `net/http`. The build image
is `golang:1.27.4-alpine3.24`. The shared kits are updated to their current
releases; see the [changelog](../../CHANGELOG.md) for versions. Several kits now
select Fiber v3.7.0 for their Fiber adapters. Warden serves HTTP with `net/http`
and does not compile Fiber packages.

## Upgrade and rollback

```sh
go get github.com/soulteary/warden@v1.7.0
```

- SDK consumers need Go 1.27.4 or later and must be rebuilt. Updating only the
  service does not replace dependencies compiled into another program.
- Keep existing Redis datasets and namespaces. Earlier production requirements
  still apply: HTTPS sources and `SNAPSHOT_READ_POLICY=enforce` by default.
- The v1.6.3 binary uses the same stored state. v1.6.3 ignores
  `REDIS_USERNAME` and the `REDIS_TLS_*` variables and connects without TLS as
  the default user; confirm that the Redis server still accepts that connection
  before rolling back. v1.6.3 also ignores `RATE_LIMIT`, `RATE_LIMIT_WINDOW`
  and the rate limit values in the configuration file.
- Rolling back restores the earlier behavior of the items listed above,
  including the unbounded HMAC body read and the full `/v1/lookup` response.
- For SDK consumers, restore the application's pre-upgrade `go.mod` and
  `go.sum` and rebuild. Verify selected versions with `go list -m`.

For versions older than v1.6.0, retain the
[v1.6.0 migration requirements](v1.6.0.md). See the
[Chinese upgrade guide](../zhCN/UPGRADE_V1_7_0.md).

## Verification

Verify the signed tag and source commit, the Go module checksum, the release
workflow run, the asset hashes in `checksums.txt`, the SPDX SBOM, and the image
digest with its keyless signature. `warden --version` prints the version,
commit and build date of a binary.
